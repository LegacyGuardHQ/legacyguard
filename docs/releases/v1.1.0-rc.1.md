# LegacyGuard v1.1.0-rc.1 release notes

**ALPHA PRERELEASE — SYNTHETIC-DATA TESTING ONLY**

This prerelease was tagged and published on 2026-08-26. It is not a stable or
production-ready release. LegacyGuard is not currently approved for real
personal, financial, medical, estate, credential, or sensitive document data.
No public production application is available.

## Major additions

- Workspace dashboard and Asset Management, Beneficiary Management, and Document Vault interfaces
- Discovery integration including scan history/detail, Review Queue, finding detail, and confirmed-finding-to-asset conversion
- Frontend design tokens, accessibility improvements, reusable state/loading components, and Storybook guidance
- PostgreSQL/Psycopg compatibility while retaining SQLite for local development and isolated tests

## Security and reliability

- Explicit non-test secret configuration, bounded uploads and registration inputs, registration throttling, shared database-backed login limiting, and bounded Discovery concurrency
- Deployment-aware document storage and Alembic database configuration
- Dependency auditing, immutable GitHub Action pins, checkout credential hardening, Dependabot, and a guarded CodeQL workflow
- PostgreSQL migration/testing, backend/frontend release checks, an RC readiness gate, and isolated synthetic deployment smoke testing

## Documentation and repository readiness

The repository now includes AGPL-3.0 licensing, governance, contribution, support, security reporting, deployment, changelog, and project-state guidance. Repository-source readiness remains separate from application production readiness.

## Known limitations

Custom CodeQL workflows now complete Python and JavaScript/TypeScript analysis
on the canonical repository; GitHub default setup remains unconfigured.
Production configuration requires PostgreSQL and object storage and rejects
uploads without a configured malware scanner. A real scanner/quarantine
integration, tested operational backup/restore and key recovery, managed
infrastructure, trusted ingress/proxy configuration, production-grade rate
limiting, privacy-safe observability, staging/security testing, production
domains, managed key rotation, retention/deletion policies, and independent
security/privacy review remain required before real-data use.

A future final-release record should identify its exact signed tag and commit
SHA and include artifact checksums, a signature or attestation, and completed
validation results when those artifacts exist.
