# LegacyGuard v1.1.0-rc.1 release notes draft

**RELEASE CANDIDATE — SYNTHETIC-DATA TESTING ONLY**

This release has not yet been tagged or published. LegacyGuard is not currently approved for real personal, financial, medical, estate, credential, or sensitive document data. No public production application is available.

## Major additions

- Workspace dashboard and Asset Management, Beneficiary Management, and Document Vault interfaces
- Discovery integration including scan history/detail, Review Queue, finding detail, and confirmed-finding-to-asset conversion
- Frontend design tokens, accessibility improvements, reusable state/loading components, and Storybook guidance
- PostgreSQL/Psycopg compatibility while retaining SQLite for local development and isolated tests

## Security and reliability

- Explicit non-test secret configuration, bounded uploads and registration inputs, registration throttling, shared database-backed login limiting, and bounded Discovery concurrency
- Deployment-aware document storage and Alembic database configuration
- Dependency auditing, immutable GitHub Action pins, checkout credential hardening, Dependabot, and a guarded CodeQL workflow
- PostgreSQL migration/testing, backend/frontend release checks, an RC readiness gate, and production-style synthetic smoke testing

## Documentation and repository readiness

The repository now includes AGPL-3.0 licensing, governance, contribution, support, security reporting, deployment, changelog, and project-state guidance. Repository-source readiness remains separate from application production readiness.

## Known limitations

CodeQL is deferred until repository eligibility and configuration permit it; these notes do not claim a completed CodeQL analysis. Managed encrypted document storage, malware scanning/quarantine, tested operational backup/restore and key recovery, managed PostgreSQL infrastructure, trusted ingress/proxy configuration, production-grade rate limiting, privacy-safe observability, staging/security testing, production domains, managed key rotation, retention/deletion policies, and independent security/privacy review remain required before real-data use.

The final release record must add the exact signed tag, commit SHA, artifact checksums/signature or attestation, and completed validation results.
