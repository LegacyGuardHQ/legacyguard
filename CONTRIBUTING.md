# Contributing to LegacyGuard

LegacyGuard is temporary project branding for pre-production software. Use
synthetic data only. Issues and Discussions may be used for non-sensitive
feedback, but unsolicited code contributions and pull requests are not
accepted.

## Feedback and security reports

Use the issue forms for ordinary bugs or proposals. Do not include real
personal, financial, medical, estate, document, credential, or other sensitive
information. Report suspected vulnerabilities only through the private
reporting guidance in [SECURITY.md](SECURITY.md), never in a public issue,
discussion, or pull request.

Opening an issue or participating in a discussion does not transfer copyright,
grant a license, or authorize the project to incorporate submitted code or
other copyrightable material.

## Pull requests and contribution terms

Submit a pull request only when the project owner has specifically requested
or authorized it. Before accepting outside copyrightable work, the owner must
publish contribution and licensing terms and confirm the applicable intake
process. No DCO or CLA has been selected. Do not begin implementation work on
the assumption that a proposed contribution will be accepted.

The repository is licensed under AGPL-3.0 (see `LICENSE`), and James Herrera is
the current individual copyright holder. Based on the repository provenance
review and owner attestation, publication authority and provenance for the
existing project materials have been reviewed; this is not formal legal
clearance. The license does not establish terms for future outside
contributions, which remain governed by the policy above. The owner must
establish contribution terms before accepting external code.

## Development guidance for authorized work

For work explicitly authorized by the owner, use synthetic data, preserve
owner-scoped access and privacy safeguards, include proportionate tests, and
document security or data-lifecycle impacts. Follow the development checks in
[README.md](README.md). An authorized pull request must complete the repository
pull-request template and receive the required review before merge.
